# ADR 0011：内部非常规订单与统一商务策略

## 决策

订单来源与收费结论使用两个独立事实表达：`creationMode` 区分常规销售订单和内部非常规订单，`chargeMode` 区分收费与免费。内部非常规订单不设置所属销售，不新增业务分类、编号步骤或顶层工作流状态；其第一步仍使用底层 `DEPOSIT_PENDING`，界面派生显示“商务确认”。

设计师、技术拆单员、订单管理员和董事长可以发起内部非常规订单。设计师创建正单时只能分配本人；其他允许角色选择启用设计师。创建人只提交收费意向和非常规原因，不提交金额或付款事实。

订单管理员通过一个原子操作锁定最终商务方式：

- 收费单同时写入最终合同金额与一笔定金报备，财务核验实际到账后开放设计；后续尾款也由订单管理员报备、财务核验。
- 免费单写入批准人、原因和时间后直接开放设计，不创建零元定金、预付款或尾款记录。

发货等下游模块只依赖统一商务策略给出的“付款门禁已满足”结论，不自行推测付款状态。已批准免费单满足该结论，但仍完整参与生产、发货、安装、验收、售后和四项成本归集。

## 权限边界

- 所有销售及销售主管均不能查看内部非常规订单，也不产生相关待办。
- 非常规收费单金额仅订单管理员、财务和董事长可见。
- 非常规收费单付款凭证仅订单管理员和财务可上传、列出或下载。
- 免费单没有合同收入，毛利为“不适用”，不能按零收入计算。

## 兼容

历史订单迁移为 `SALES_STANDARD + CHARGED`，金额、所属销售、编号、付款事实和事件均不改写。创建人优先从最早的 `ORDER_CREATED` 事件回填，无法确定时保持为空。

## 结果

- 常规与非常规订单共享一套后续履约流程和编号池。
- 免费是明确业务结论，而不是伪造付款完成。
- 付款责任、金额权限、凭证权限、待办和发货门禁均由同一商务策略解释。
- 商务方式确认后不可由普通改额动作在收费与免费之间切换。
