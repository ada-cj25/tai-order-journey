# “苔的跟单旅程”本轮实现与验证记录

日期：2026-08-31。结论：个人低成本上线所需的代码、部署模板、只读手机页和操作手册已准备完成；**不等于域名、云资源或备案已经办理，也不等于已经开放生产访问。**

## 已实现

- 产品名称统一为“苔的跟单旅程”，新增 `/mobile` 董事长管理员只读入口；移动会话的只读限制由服务端执行，不能靠直接调用写接口绕过。
- 新增 `deploy/personal/`：Caddy 同域名 HTTPS 入口、NestJS API、Docker 内部 PostgreSQL 17、持久卷、独立迁移任务、COS 附件、成本关闭及确定镜像 digest 发布配置。
- 新增空正式库初始化工具，只创建首位管理员和六个编号池；不运行演示 seed，首位管理员首次登录必须改密。
- 新增每 6 小时数据库备份、独立 COS 备份凭证、SHA-256/大小校验、私有加密对象上传和隔离恢复演练脚本。
- 新增个人办理与部署手册、试用及数据处理授权书模板、云端验收清单；公司官网和 `norli.com.cn` 不在本次变更范围。
- 生产启动继续强制要求安全会话密钥、HTTPS、COS 和 `COST_MODULE_ENABLED=false`；Swagger 与开发服务器不进入生产入口。
- Sites 构建能力继续保留，仅作为静态原型交付物，不承载正式 ERP。

## Git 数据边界

- `.env`、密钥、证书、数据库备份和上传目录均被忽略。
- `design-audit/` 和 `outputs/` 仅留在本机，不进入首个 Git 基线；其中可能包含验收截图、照片转录表格和业务资料。
- 代码库中的 `*.example` 只放占位符，不保存真实腾讯云 SecretKey、数据库密码或正式会话密钥。
- 成本验收 fixture 和文字记录继续保留为明确标注的测试资料，不会由正式初始化工具导入生产库。
