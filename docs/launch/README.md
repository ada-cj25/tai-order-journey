# “苔的跟单旅程”云端测试与上线工作台

当前执行路线是公司主体已备案的新域名及上海轻量服务器；云账号持有方式以实际实名、备案条件和双方授权为准，TCR“个人版”不代表账号实名类型。开发者保留产品和代码所有权；公司业务数据归公司。`norli.com.cn` 和现有公司网站不变。

## 当前阶段：公司云测试

按 [公司云测试逐步部署手册](company-cloud-test-runbook.md) 在独立 PostgreSQL 数据库和私有 COS 桶部署。只录入编造数据；测试库不转为正式库，也不导入本地演示订单。成本模块仅在该隔离测试环境开启。先完成云端技术验收，再发员工登录地址。

现有 `deploy/personal/` 提供镜像、数据库、Caddy、备份和恢复的基础部署组件；`deploy/company-test/` 提供公司测试环境覆盖配置及独立初始化。使用两份 Compose 文件时，必须把公司测试覆盖文件列在后面。正式环境继续默认关闭成本模块。

## 后续正式试点

员工模拟测试通过后，另建空的正式环境，独立核对编号池、收款账户、权限与备份。旧订单留在旧流程，先录少量真实新单；按 [桌面岗位验收](acceptance.md) 和正式试点清单完成业务、技术签字后扩大使用。处理真实公司数据前须有签妥的 [试用及数据处理授权](data-authorization-template.md)。

## Core 分支验证范围

当前 main 只保留网页、小程序、后端及运行/部署依赖。运行 `npm run check` 验证客户端生成、类型、构建和静态打包；完整业务回归、数据库集成测试及开发文档保留在原工作区及精简前 Git 提交中。代码可构建不代替下面的岗位、权限、备份恢复和发布验收。
