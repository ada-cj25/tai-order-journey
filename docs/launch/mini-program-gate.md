# 微信小程序下一阶段（本地并行开发，生产接入仍受门槛约束）

本文件同时是开发边界与发布验收契约。2026-09-14 已完成本地十类在用岗位工作台、微信邀请码绑定模型、独立移动 Token、移动专用DTO和写接口白名单；它们仍默认关闭，不代表已经允许接入真实微信身份或真实客户数据。云端附件联调、主体与备案、隐私材料、负向权限验收、提审和发布仍须满足下述启动条件。

## 生产接入与提审启动条件

桌面跨岗验收签字；公司微信主体/AppID/类目/备案与隐私材料；云测试API与私有附件联调；指定审核测试账号。密钥只配置后端，审核账号使用模拟数据，不能给审核方真实客户资料。

## 本地并行开发边界

- 已完成本地实现：十类在用岗位动态导航和工作台、两类销售层级与车间主管模拟账号、销售/财务/设计/采购/发货/安装/售后/车间轻量原生表单、技术桌面交接卡、站内消息、扫码定位、服务端草稿及30秒轮询。
- 已完成待联调接口：邀请码与微信绑定、2小时 Access Token、30天 Refresh Token、移动专用订单DTO、角色写操作白名单、幂等键、版本冲突、受控附件上传。
- 暂不宣称完成：真实微信平台 code 联调、云端私有附件、审核主体测试、真实客户数据接入、微信订阅消息和生产发布。
- `web-view` 仅作为复杂只读页面的可选桥接层；核心报工、异常、安装、发货和销售填写保持原生页面，避免主体或业务域名能力变化导致核心流程不可用。

## 原生TypeScript轻量页面

一个小程序按服务端岗位进入独立工作区：董事长（风险及少量关键覆盖）、销售（建单和本人付款报备）、订单管理员（发货和外购到货）、财务（付款核验）、设计师（接单、退回和转交）、技术（任务摘要与电脑端交接）、采购（路线放行与区域五金包确认）、四车间工人与主管（扫码逐工序报工）、安装（本人车次和验收）、售后（履约完成订单队列）。成本调价、完整成本明细、技术审单、CAD/海迅/物料Excel及其解析结果、批量车间完成仍不开放给小程序。

历史 `WAREHOUSE` 角色不生成邀请码且不能登录。所有岗位共用微信绑定与移动会话；退出仅撤销当前设备会话并清理本地业务缓存，保留微信绑定。员工停用、改岗、品牌/车间调整、密码重置或管理员解除绑定后，旧会话通过 `sessionVersion` 或显式撤销立即失效。

销售移动范围继续使用桌面端同一条服务端规则：普通销售仅限 `salesId=当前员工` 且属于本品牌的常规订单；销售主管可查看本品牌正单和补单，但不能读取其他销售的付款金额/凭证，也不能代替其他销售提交收款报备。小程序展示的“本人范围/品牌范围”只是规则说明，不承担授权判断。

## 计划中的接口/数据

| 能力 | 计划服务端约束 | 必测负向场景 |
|---|---|---|
| 微信登录与绑定 | 后端验证微信code；24小时一次邀请码；openid哈希只映射现有员工；订单管理员/董事长在网页生成与撤销 | 重复code、过期邀请、非员工、自选角色拒绝 |
| 移动会话 | 可撤销token记录、到期、员工sessionVersion；明确client=mini | 停用/改岗立即失效；不能拿移动token调用桌面写接口 |
| 移动查询 | 与桌面共用orderScope，使用移动专用DTO返回岗位所需字段；大文件只返回数量、版本和状态 | 销售按本人/品牌主管范围；设计/安装仅本人；售后仅履约订单；敏感字段按权限；CAD、海迅和物料明细不可下载 |
| 移动动作 | 复用同一工作流服务和事务；mobile专属动作白名单 | 跨岗位、跨订单、跨安装负责人直调URL必须拒绝；移动Token不能调用桌面专属写接口 |
| 工序定位 | QR仅含不可猜测的定位标识，不含联系方式、地址或凭证 | 无登录扫码仍拒绝，跨工序拒绝，前序未完拒绝 |
| 文件 | 仍需订单归属和角色检查；受控上传与短期授权下载或后端代理 | 他人附件、错误类型、重复上传、权限撤销 |
| 消息 | 站内待办是事实源，微信发送有授权与模板检查、状态及错误记录 | 未授权/不可用/失败不阻断业务，不显示假送达 |

所有移动业务提交使用一次 `Idempotency-Key`，超时重试保留原标识和原内容；若用户修改内容则生成新标识。带服务器返回的 `X-Expected-Updated-At`；409时刷新并请用户复核，不自动覆盖；服务器成功才显示完成。断网保留本机待提交内容，首期不离线推进工序。

当前桌面幂等保护覆盖：建单、工作流提交、草稿、采购完成、报工、售后新建和旧流程编号预留；对现有订单阶段/数量写入另做版本检查。不得推断其他接口也自动获得幂等。整版撤销、历史计划补录已加同订单事务锁，但仍须补其完整异常和重试验收，移动端不开放这些动作。

## 开关与环境

- 后端 `.env` 必须显式设置 `MINI_PROGRAM_ENABLED=true` 才会接受任何移动认证；默认示例为 `false`。
- 公司云测试小程序 `config/runtime.ts` 的 `packagedProfile` 必须改为 `company-test-api`，使用 HTTPS API 地址。开发者工具的本机 `local-api` 开关只访问 `127.0.0.1:3000`，不能在手机真机或云端使用，也不能作为发布验收。
- `WECHAT_MINI_APP_SECRET` 只存在服务端，禁止提交仓库或写入小程序包。
- 本机演示继续使用 `mode: "mock"`，不会访问真实编号池；本机 API 联调需显式设置 `MINI_PROGRAM_ENABLED=true` 与 `MINI_PROGRAM_DEV_LOGIN_ENABLED=true`，只有本机数据库、本机网页 origin 和开发者工具模拟器同时满足条件才接受 `TEST-WX-*` 身份。该测试只验证业务 API，不验证微信 code2Session。
